# Circle Clash — архитектура

## Границы ответственности

- **React** управляет страницами, меню, профилем, авторизацией и настройками.
- **Phaser** создаёт арену, временных бойцов, HUD и визуальные эффекты боя.
- **CombatSimulation** содержит правила боя и не импортирует React, Phaser, DOM или Supabase.
- **Supabase** остаётся инфраструктурой аккаунта и будущей постоянной статистики. Запросов к нему
  внутри игрового цикла нет.

## Поток данных

```text
клавиатура / gamepad
        ↓
InputManager → абстрактные GameAction
        ↓
FixedStepLoop (60 Гц) → CombatSimulation
        ↓
сериализуемый SimulationSnapshot
        ↓
FightScene → Phaser renderers и HUD
```

`ReactGameBridge` передаёт только события жизненного цикла между React и Phaser: готовность,
пауза, запрос выхода и уничтожение игры. Он не хранит состояние боя.

## Жизненный цикл Phaser

`GameCanvas` создаёт `Phaser.Game` внутри `useEffect`. При cleanup он:

1. отписывает события моста;
2. отключает `ResizeObserver`;
3. вызывает `game.destroy(true)`;
4. очищает контейнер canvas.

Такой порядок выдерживает двойной mount/unmount в React Strict Mode и не оставляет лишний canvas.

## Игровое время

Phaser передаёт реальный `delta` кадра в `FixedStepLoop`. Цикл накапливает время и вызывает
симуляцию шагами `1 / 60` секунды. Поэтому скорость движения, гравитация, урон и столкновения не
зависят от FPS браузера.

## Сериализация

`SimulationSnapshot` состоит только из чисел, строк, boolean, `null` и обычных объектов. Снимок
можно передать через `JSON.stringify`, сохранить для отладки или восстановить через
`CombatSimulation.restore`. Сетевой rollback намеренно не реализован на этом этапе.

## Маршрутизация

Таблица маршрутов находится в `src/app/router.tsx`. Сохраняется уже установленный `wouter`;
Vercel rewrite из `vercel.json` поддерживает прямое открытие SPA-маршрутов.
